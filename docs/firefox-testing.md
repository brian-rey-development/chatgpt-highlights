# Testing the Firefox build in a real Firefox

Playwright's Firefox is a patched build driven through Juggler and has no support for loading WebExtensions, so the Playwright projects can only exercise the Chromium build. That left `dist/firefox-mv3`, with its own manifest and event-page background, unchecked in any real browser.

## Options considered

`web-ext run` installs the extension into Firefox through the remote debugging protocol and is good for manual work, but it gives a test no handle on the page. geckodriver with `installAddon` works and is the usual route, yet it needs a geckodriver binary and selenium-webdriver, which are downloads and new dependencies. Marionette is the protocol geckodriver itself speaks, it is built into every Firefox that starts with `--marionette`, and its `Addon:Install` command accepts an unpacked directory as a temporary add-on, so a small Node client needs no dependency at all.

## What `pnpm e2e:firefox` does

It builds the Firefox extension, starts the installed Firefox headless with a throwaway profile, installs `dist/firefox-mv3` through Marionette, serves a bare page over HTTPS with a self-signed certificate generated by openssl, and maps chatgpt.com to localhost with the `network.dns.localDomains` preference. Match patterns ignore ports, so the content script runs on `https://chatgpt.com:<port>/c/<id>`. The test passes when the add-on id equals the one in the manifest and the overlay host element appears on the page. It ran three times in a row in about 1.5 seconds each on Firefox 158 on macOS.

It lives in `e2e/firefox`, has its own Playwright config, and is ignored by the default config, so `pnpm e2e` is unchanged. It needs Firefox in a standard location or in `FIREFOX_BIN`, and openssl on the path.

## Limits and next step

The production build keeps its shadow root closed, so this smoke test cannot click the pill. Highlighting in Firefox end to end needs the ChatGPT-shaped page and mock endpoints now implemented as Playwright routes in `e2e/mock-backend.ts` to be served by the fixture server instead, plus a Firefox build in the `e2e` mode with an open root. That is worth doing once a Firefox-only regression shows up, and the Marionette client in `e2e/firefox/marionette.ts` already supports it through `WebDriver:ExecuteScript`.
